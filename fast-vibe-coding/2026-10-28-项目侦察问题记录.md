## 二、问题详情：分析过程与处理结果

### P1（阻塞）：本机缺少 .NET SDK

**现象**

```
$ dotnet sln list
Exit code 145
The application 'sln' does not exist.
No .NET SDKs were found.
Download a .NET SDK: https://aka.ms/dotnet/download
```

**分析**

- `dotnet` 可执行文件存在：`C:\Program Files\dotnet\dotnet`。
- `dotnet --list-sdks` 输出为空；`dotnet --list-runtimes` 只有：
  ```
  Microsoft.NETCore.App 8.0.33
  Microsoft.WindowsDesktop.App 8.0.33
  ```
- 两个项目 TFM 均为 **`net10.0`**，主项目还使用 `Native AOT`、`PublishTrimmed`、`GeneratedComInterface` 等 .NET 9/10 特性。
- 结论：这不是项目配置错误，而是**本机环境缺 SDK**。运行时 8.0 既不能用于 `dotnet build`，也不能直接运行 net10.0 产物。

**处理结果**

1. 改用直接解析 `.sln` 文本完成项目清单侦察（结果见第四节）。
2. 未修改仓库任何构建配置来"迁就"本机环境（降 TFM 会破坏 AOT/COM 源生成链路，且与 CI 使用的 .NET 10 不一致）。
3. **待办**：安装 .NET 10 SDK（`winget install Microsoft.DotNet.SDK.10` 或官网安装包），安装后执行
   ```
   dotnet restore ArchivePasswordTestTool.sln
   dotnet build ArchivePasswordTestTool.sln -c Release
   dotnet test ArchivePasswordTestTool.Tests\ArchivePasswordTestTool.Tests.csproj
   ```
   作为基线验证。

### P2：无 `global.json`，SDK 版本不受约束

**分析**

`Glob("**/global.json")` 无结果。项目 TFM 是 `net10.0`，任何装了 ≥10 SDK 的机器都能构建，但未来 SDK 大版本升级（如 11）可能改变 AOT/裁剪行为，而本地与 CI 之间没有版本锁。

**处理结果**

仅记录。是否引入 `global.json`（`rollForward: latestFeature` 之类）需与 CI 的 `windows-latest` 镜像策略一起决定，属于较大改动，暂不擅自添加。

---

### P3：无共享构建配置

**分析**

`Directory.Build.props`、`Directory.Packages.props`、`Directory.Build.targets`、`NuGet.config` 均不存在。两个项目各自写 `TargetFramework` / `Nullable` / `WarningLevel`，包版本直接写在各 `.csproj` 里（`Spectre.Console 0.57.2`、`xunit 2.9.2` 等）。

当前只有 2 个项目，重复量小，不构成实际故障；一旦新增项目（例如拆出 `Interop` 程序集）就会出现配置漂移。

**处理结果**

仅记录，未改动。

---

### P4：构建期外部工具依赖与网络

**分析**

从 `.csproj` 与 `docs/DEVELOPMENT.md` 确认，构建会按需下载：

| 工具 | 用途 | 缺失后果 |
|------|------|----------|
| `resvg` | 把 `build/AppIcon.svg` 渲染成 8 档 PNG，生成 `AppIcon.ico` | **构建失败**（`GenerateAppIcon` 显式 `Error`） |
| `upx` | 压缩 AOT 原生产物 | 警告并跳过压缩，产物约 11 MB |
| 7-Zip 安装包 + `7zr.exe` | 提取并内嵌 `7z.dll` + `License.txt` | 警告并跳过内嵌；CI 传 `RequireEmbeddedSevenZip=true` 时失败 |

`tools/` 目录当前不存在，首次构建必然联网。`resvg` 缺失时构建会硬失败，这是有意设计（图标属于产物的一部分），但意味着**离线环境无法直接构建**。

**处理结果**

仅记录，未改动。后续若需要离线/可复现构建，可手工放置 `tools/resvg/resvg.exe`、`tools/upx/upx.exe`、`tools/7zip/7z.dll`，或用 `-p:ResvgPath=...` / `-p:UpxPath=...` 指定。

### P5：无 `pre-commit` 钩子

**分析**

`.git/hooks/` 只有 `*.sample`，无生效钩子。编码约定（UTF-8 无 BOM、CRLF）由以下方式守护：

- 根目录 `.editorconfig`（`root = true`、`charset = utf-8`、`end_of_line = crlf`）
- `.gitattributes` 的 `* text=auto`（仓库内统一 LF，工作区按平台检出）
- `SourceEncodingTests`（全仓源码 UTF-8 无 BOM）
- `LocalizationTests`（五套 resx 键集/占位符一致）

即"提交时"没有拦截，问题会在测试阶段才暴露。

**处理结果**

仅记录，未改动。是否加入钩子需用户决定（会改所有协作者的本地行为）。

---

### P6：手工维护的 `Resources.Designer.cs`

**分析**

`docs/DEVELOPMENT.md` 明确：`Resources.Designer.cs` 为手工维护（中文注释、人工排序），csproj 刻意移除了 `Generator`/`LastGenOutput`，防止 VS 设计器保存 resx 时覆盖它。因此新增 resx 键必须同步加属性，否则代码无法强类型引用；键集不一致有 `LocalizationTests` 兜底。

**处理结果**

仅记录。后续涉及多语言文案的改动，必须成对修改 resx（5 套）+ `Designer.cs`。

## 三、侦察结论（技术栈）

- **解决方案**：`ArchivePasswordTestTool.sln`，2 个项目（主程序 + xUnit 测试）。
- **类型**：Windows-only **控制台应用**（Spectre.Console 终端 UI），**不是** ASP.NET Core / EF Core / WPF / WinForms / Blazor。
- **运行时形态**：Native AOT + UPX 单文件发布；通过 `7z.dll` 的 **COM 互操作**（`GeneratedComInterface` / `GeneratedComClass`）+ P/Invoke 工作。
- **业务模块**：`Cli/`（参数与进程模式）、`Interop/`（7-Zip COM、库加载、格式检测、Win32）、`Services/`（Runner / Planner / MultiProcess / Upgrade / OnlineService / PasswordDictionary / ResultsWriter / HttpTransport 等）、`Ui/`、`Properties/`（5 语言 resx）。
- **测试**：xUnit 2.9.2，17 个文件、121 处 `[Fact]/[Theory]/[InlineData]/[ClassData]`；部分用例依赖外部 7-Zip CLI / WinRAR，缺失时自动跳过。
- **CI**：`ci.yml` / `release.yml` → 共用的 `.github/actions/build-verify`：restore → build → test → publish 单文件 → publish AOT → 冒烟测试（4 组矩阵）。
