## 1. 背景与目标

现状一次只能处理「一个密码字典 + 一个压缩包」，完成后程序退出。用户需要：

1. 预先指定**多个密码字典文件**，按顺序处理；
2. 处理完成后**停留在程序内**，等待用户输入下一轮设置；
3. 一次处理**多个压缩包文件**，并支持直接传入**文件夹**。

**目标**：在不改变单包用法与现有退出码语义的前提下，把执行模型从「单任务」升级为「批量 + 可选多轮」。

**非目标**：

- 不新增 GUI，仍为终端交互；
- 不改变 `-Worker` 多进程协议与 `7z.dll` 互操作层；
- 不递归解压「压缩包内的压缩包」；
- 不引入新的配置文件格式（字典与路径均来自 CLI 或交互输入）。

## 2. 已确认的需求决策

| 编号 | 决策点 | 结论 |
|------|--------|------|
| D1 | 多字典语义 | **合并为有序去重队列**，按 `-D` 出现顺序进入队列，找到即停 |
| D2 | 多路径语法 | **重复 `-D` / `-F`**，向后兼容单值写法 |
| D3 | 文件夹扫描 | **递归 + 扩展名初筛 + 签名确认**，分卷只取 `.001` |
| D4 | 循环适用范围 | **仅交互模式**（无参数启动且终端可交互）；带参批处理跑完退出 |
| D5 | 扩展名白名单 | `.7z`、`.zip`、`.rar`、`.exe`（SFX）、`.001`（分卷首卷） |
| D6 | 结果保存 | 批量开始前**整批询问一次**，逐包写结果文件 |
| D7 | 下一轮设置 | 默认**沿用上一轮字典**，仅重新选择压缩包/文件夹 |
| D8 | 隐藏/系统文件 | 文件夹扫描时**跳过**隐藏与系统属性文件 |

## 3. 术语

- **字典队列**：多个字典按顺序合并、全局去重后的密码序列。
- **批（Batch）**：一轮设置展开后得到的压缩包集合。
- **轮（Round）**：交互模式下「一组设置 + 一次批处理」的完整过程。

## 4. 功能设计

### 4.1 命令行变更

```text
# 多字典（按出现顺序）
ArchivePasswordTestTool.exe -D a.txt -D b.txt -F x.7z

# 多压缩包 + 文件夹混合
ArchivePasswordTestTool.exe -D dict.txt -F a.7z -F D:\archives -F b.zip

# 单值写法保持有效
ArchivePasswordTestTool.exe -D dict.txt -F a.7z
```

- 每个 `-D` 的值必须是已存在文件；每个 `-F` 的值必须是已存在的文件或目录。
- 校验失败抛出 `FileNotFoundException`，沿用现有「打印 + exit 1」路径。
- 不新增循环开关；是否循环由「无参数启动 + 终端可交互」决定。
- `-lib`、`-Api`、`-NoQuery`、`-NoReport` 语义不变。

### 4.2 交互流程

```text
输入字典（可一次拖入多个，逐个追加，空行结束）
  → 输入压缩包/文件夹（同上）
  → 文件夹展开为压缩包列表
  → 逐包测密（第 i/n 个）
  → 批量汇总
  → 询问：继续下一轮？
      是 → 沿用字典，仅重选压缩包/文件夹 → 回到展开
      否 / 空行 / Ctrl+C → 退出
```

- 一次拖入多个文件时，按引号与空白拆分路径；每个路径单独校验。
- stdin 被重定向时：不循环、不弹保存确认、按单轮批处理执行。
- 标题与备用屏幕在整个会话期间保持，仅批量结束时恢复。

### 4.3 多字典合并规则

- 顺序：在线共享密码（若有）→ 字典 1 → 字典 2 → …
- 全局去重使用 `StringComparer.Ordinal`，保留首次出现位置。
- **每个文件独立进行编码探测**（GBK / UTF-8 / BOM / 系统 ANSI），界面分别提示非 UTF-8 的字典。
- 跨压缩包复用时通过 `Reset()` 回到队列起点；密码集合常驻内存（不再逐槽释放）。
- 并行与多进程模式不保证逐行顺序；保证的是「前一个字典的密码先进入队列」与「找到即停」。

### 4.4 文件夹展开规则

| 规则 | 说明 |
|------|------|
| 递归 | 遍历所有子目录 |
| 扩展名初筛 | `.7z` / `.zip` / `.rar` / `.exe` / `.001`，其余不读文件头 |
| 签名确认 | 复用 `ArchiveFormatDetector.DetectArchiveFormat`，识别 7z / zip / rar4 / rar5 / SFX |
| 分卷 | 只接受 `.001`；`.002` 及以后跳过 |
| 隐藏/系统文件 | 跳过（`FileAttributes.Hidden` / `System`） |
| 去重 | 按 `Path.GetFullPath` + 忽略大小写去重 |
| 顺序 | 输入列表顺序优先；同一目录内按文件名排序 |
| 跳过统计 | 无权限、无法识别、非首卷分别计数，批量开始前提示 |
| 空结果 | 打印错误并 exit 1 |

### 4.5 批量执行与结果

- 压缩包**串行**处理；单个包内部仍按现有线程/多进程策略并行。
- 单包失败（格式不识别、文件损坏、打开失败）记录失败原因后**继续**处理其余包。
- 每包独立展示信息面板、进度条与结果面板，标题显示「第 i/n 个」。
- 在线查询/回传按每个压缩包各自的哈希执行，语义不变。
- 未加密包输出「未加密」结论后继续。
- 结果文件：每包写 `原路径[results].txt`；批量开始前统一询问一次是否保存。
- 整批退出码：全部处理完成（含未找到密码）为 `0`；任一包失败或启动错误为 `1`。

### 4.6 下一轮循环

- 仅当 `Console` 输入输出均为交互终端时启用。
- 下一轮默认沿用上一轮字典与其他开关，仅重新询问压缩包/文件夹。
- 留空或选择「否」结束会话；`Ctrl+C` 立即退出。
- 自我替换、更新检查在整个会话开始时各执行一次，不随轮次重复。

## 5. 架构改动

```text
现状：
Program.Main → Instance.Execute → Runner.Run
                                   ├─ Options.Parse
                                   ├─ 单包测密
                                   ├─ 结果输出
                                   └─ ResultsWriter

目标：
Program.Main → Instance.Execute → BatchRunner.Run
                                   ├─ Options.Parse（一次）
                                   ├─ ArchiveEnumerator.Expand
                                   ├─ PasswordDictionary（多文件 + Reset）
                                   ├─ foreach 压缩包 → Runner.Run(单任务) → TestOutcome
                                   ├─ ResultsWriter（整批）
                                   ├─ 汇总
                                   └─ 交互下一轮
```

| 组件 | 职责 |
|------|------|
| `Cli/Options` | 只负责参数解析与校验，产出多值列表 |
| `Services/ArchiveEnumerator` | 输入（文件/目录）→ 确定的压缩包列表 |
| `Services/PasswordDictionary` | 多文件有序合并、编码探测、跨包重置 |
| `Services/Runner` | 单个压缩包的一次完整测密，返回 `TestOutcome` |
| `Services/BatchRunner` | 批量编排、失败继续、汇总、多轮循环、退出码 |
| `Services/Planner` | 生命周期与单个压缩包绑定，包间释放上下文池 |

## 14. 真实交互回归修复（2026-10-29）

**现象**：真实终端启动后始终停在「请将密码本拖入本窗口」，一次拖入多个字典也无法进入下一步。

**根因（两处叠加）**：

1. Windows 控制台一次拖入多个文件时，无空格路径不加引号，实际输入形如
   `C:\a.txt C:\b.txt`；旧 `SplitPaths` 在「无引号」时把整行当成一个路径，
   校验必然失败并原地重问。
2. 接受路径后只重印标题、不重印结束方式的提示，用户不知道要空输入 + Enter。

**修复**：

- `SplitPaths` 改为按引号/空白分词（引号内空白保留）；
- 新增 `ResolvePaths`：整串存在时优先作为单个路径，否则再拆分，
  兼顾「手输含空格路径」与「一次拖入多个无空格路径」；
- 每次接受一批路径后重印提示，并明确「直接按 Enter（空输入）结束本列表」；
- 对刚输入/拖入且已收下的路径再按 Enter，直接视为结束（不必再按空 Enter）；
- 5 种语言的提示文案同步。

**验证**：新增 `ResolvePaths` 单测与「交互模式一行输入两个字典」E2E；
`dotnet test` 190 通过 / 0 失败。真实拖放与 stdin 行输入走同一套解析逻辑。
