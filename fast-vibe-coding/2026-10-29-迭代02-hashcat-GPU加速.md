## 1. 背景与目标

在现有 CPU（多进程/线程）测密基础上，为 **header 加密的 7z** 与 **WinZip AES 的 ZIP**
增加可选 GPU 加速。GPU 后端采用 **hashcat 6.x（OpenCL）**，程序自身不实现密码学内核。

非目标：

- 普通 7z（仅文件数据加密）：验证需要解压，GPU 无有效路径；
- ZIP ZipCrypto：无 KDF，GPU 收益有限；
- RAR4 / RAR5：格式专有，后续单独评估；
- 自动下载或分发 hashcat。

## 4. 哈希格式（来自 hashcat 6.2.6 模块源码）

### 7z（mode 11600）

```text
$7z$<type>$<cycles>$<saltLen>$<saltHex>$<ivLen>$<ivHex>$<crc>$<dataLen>$<unpackSize>$<dataHex>
```

- 仅接受 `type == 0`（header 加密）；`type == 2` 是普通 7z，转为 CPU。
- `ivHex` 固定 16 字节（32 hex）；`crc` 为解密后 header 的 CRC32（十进制）。
- 由 `7z2hashcat` 生成，程序只做字段校验，不自行解析 7z 结构。
- 分卷 7z：7z2hashcat 2.0 对当前分卷样本报 seek 错误 → **回退 CPU**（首期边界）。

### ZIP AES（mode 13600）

```text
$zip2$*0*<mode>*0*<saltHex>*<verifyHex>*<cipherLengthHex>*<dataHex>*<authHex>*$/zip2$
```

- `mode`：1 = AES-128（salt 8）、2 = AES-192（salt 12）、3 = AES-256（salt 16）。
- `verifyHex`：2 字节密码校验值；`authHex`：10 字节认证码。
- `cipherLength`：密文长度；`dataHex`：密文本身。
- C# 解析 EOCD → 中央目录 → 本地头 → 0x9901 AES extra field，读取 salt/verifier/密文/auth。

## 5. 运行架构

```text
Runner
  ├─ HashcatLocator（AppContext.BaseDirectory\hashcat.exe）
  │    ├─ hashcat --version（要求 6.x）
  │    └─ hashcat -I（解析 Backend Device ID / Type / Vendor / Name）
  ├─ ArchiveHashExtractor
  │    ├─ 7z header → 7z2hashcat64-2.0.exe → 校验 $7z$ type 0
  │    └─ ZIP AES   → ZipAesHashReader → $zip2$
  ├─ Planner：格式支持 + 设备可用 + 字典 ≥ 阈值 → ExecutionMode.Gpu
  └─ GpuPasswordTester
       ├─ HashcatSession：-m 11600/13600、--stdin、--keep-guessing
       ├─ PasswordDictionary → stdin（保持顺序/去重/在线密码优先）
       ├─ 轮询 outfile 候选 → 7z.dll 最终确认
       └─ 失败 → dictionary.Reset() → CPU 重跑
```

## 6. 关键设计

- **最终确认**：header 加密用新建 `ArchiveContext(password)` 校验（Open 即验密）；
  普通加密用现有 `ArchiveContext.TestPassword`。hashcat 的「已破解」不直接作为结果。
- **假阳性**：ZIP AES verifier 仅 2 字节，使用 `--keep-guessing` 继续，候选逐个确认。
- **字典流式输入**：不生成临时合并词表；`PasswordDictionary.PopBatch` 降低锁开销。
- **临时文件**：hash/potfile/outfile 放在独立临时目录，`finally` 递归删除；hashcat 工作目录
  固定为程序目录（加载 `OpenCL\`、`modules\`）。
- **阈值**：按实测折算，header 7z ≥ 25,000 行、ZIP AES ≥ 500,000 行才启用 GPU；
  `APTT_GPU_MIN` 可统一覆盖。小字典低于阈值时连 hashcat 探测都不触发。
- **回退**：hashcat 缺失/过旧/无 GPU/提取失败/进程错误 → 提示原因并走 CPU。
- **不做**：普通 7z、ZipCrypto、RAR、分卷 7z 的 GPU 加速。

## 9. 风险与边界

- hashcat 仅同目录，用户需自行放置完整发行包（`hashcat.exe`、`OpenCL\`、`modules\` 等）；
  7z 另外需要 `7z2hashcat64-2.0.exe`。
- 分卷 7z、普通 7z、ZipCrypto、RAR 一律 CPU。
- CI 无 hashcat/GPU，GPU 用例跳过；ZIP 解析与回退路径必须由无 GPU 单测覆盖。
- hashcat 版本差异、AMD 驱动异常、临时文件权限 → 统一回退 CPU 并提示。
- 临时哈希含盐/密文，不写入程序目录，退出时删除。

## 11. 实施结果（2026-10-29）

- **验证环境**：系统 .NET SDK 10.0.403；hashcat 6.2.6（官方 hashcat.net）；
  GPU AMD Radeon RX 6650 XT / OpenCL 2.1。
- **实测**：
  - header 加密 7z：hashcat `-m 11600` 命中，`7z.dll` 确认 `Correct123!`；
  - AES ZIP：自研 `$zip2$` + hashcat `-m 13600` 命中并确认；
  - `-NoGpu` 与普通 7z 均正确回退 CPU。
- **测试**：`dotnet test -c Debug` → **195 通过 / 0 失败**（含 2 个真实 GPU E2E、
  ZIP 哈希结构测试、`-NoGpu` 回退）。
- **基准（RX 6650 XT）**：hashcat 7z `468 kH/s`、ZIP AES `1.34 MH/s`；
  CPU 对照 `1,234/s`（7z header）与 `33,348/s`（AES ZIP）；GPU 固定启动约 13 s，
  因此阈值按格式取 25,000 / 500,000 行。
- **与设计偏差**：
  1. 7z 哈希提取使用同目录的 `7z2hashcat64-2.0.exe`（已验证可独立运行），
     因此 GPU 模式对 7z 额外要求该工具；ZIP 侧为自研解析，不依赖 John。
  2. 分卷 7z 直接回退 CPU（7z2hashcat 2.0 分卷 seek 失败，整包复制代价过高）。
  3. 阈值按实测改为 7z 25,000 / ZIP AES 500,000；低于阈值时连 hashcat 探测都不触发，
     避免 10–15 秒固定开销。
  4. `hashcat -d <device>` 固定使用探测到的 GPU，避免 CPU OpenCL 设备混入。
- **未使用**：John jumbo 仅用于验证 `$zip2$` 格式；其 7z/ZIP 为 CPU 模式且本机检测不到
  OpenCL 设备，未纳入运行时依赖。
- **工具放置**：本地验证把 hashcat 发行包与 7z2hashcat 放到
  `ArchivePasswordTestTool/bin/Debug/net10.0`；这些文件不入库。
- **提交**：`e5658e2`（实现、文档与阈值调优）。
